# editalis-cloud

**Infrastructure for [Editalis](https://github.com/Amadeus-22/editalis): AWS with Terraform, Kubernetes with Helm and Argo CD, monitoring, and a backup that is proven by restoring it.**

Editalis is a Python service with an API, a scheduled worker and a PostgreSQL
database. This repository is everything needed to run it in the cloud, written
as code and checked by a pipeline.

---

## What is here

| Path | What it does |
|---|---|
| `terraform/modules/network` | VPC, public and private subnets, and three security groups that only allow load balancer → node → database |
| `terraform/modules/backup` | Two private, encrypted, versioned S3 buckets: database backups and logs |
| `terraform/modules/database` | PostgreSQL 16 on RDS in the private subnets, TLS enforced, password generated by RDS into Secrets Manager |
| `terraform/modules/cluster` | One EC2 instance running k3s behind an Application Load Balancer, with a least-privilege IAM role and no SSH |
| `terraform/envs/dev` | The lab environment, including a monthly budget alert |
| `chart/editalis` | Helm chart: API, worker, migration job, ingress, network policy, backup CronJob |
| `gitops/` | Argo CD Applications that deploy the chart and the monitoring rules from Git |
| `monitoring/` | Seven alert rules, a Grafana dashboard and values for kube-prometheus-stack |
| `scripts/` | Restore script, restore drill and a local Argo CD demo |
| `docs/` | Runbook and the record of every security finding that was fixed or accepted |

## Design

```
                Internet
                   │ 443
          ┌────────▼─────────┐
          │ Load balancer    │  public subnets (2 zones)
          └────────┬─────────┘
                   │ NodePort, from the load balancer only
          ┌────────▼─────────┐        ┌──────────────┐
          │ k3s node (EC2)   │───────▶│ S3 backups   │
          │ Argo CD, Editalis│  IAM   └──────────────┘
          └────────┬─────────┘
                   │ 5432, from the node only
          ┌────────▼─────────┐
          │ RDS PostgreSQL   │  private subnets, no route to the internet
          └──────────────────┘
```

Decisions that shaped it:

- **k3s on one instance instead of EKS.** The EKS control plane has a fixed
  monthly price; k3s is conformant Kubernetes and the chart does not care.
- **No NAT gateway.** Only the database lives in the private subnets and it
  needs no internet access. The node sits in a public subnet with inbound
  traffic limited to the load balancer.
- **No SSH.** The node is reached through SSM Session Manager, so there is no
  key to leak and no port 22 to scan.
- **No secrets in Git or in Terraform.** RDS generates the database password
  into Secrets Manager; the chart reads application secrets from an existing
  Kubernetes Secret.
- **`lab = true` is the only difference from production settings.** It turns
  off Multi-AZ, deletion protection and the final snapshot so the environment
  can be destroyed.

## Check everything locally

```bash
make check    # terraform fmt + validate, Checkov, Trivy, helm lint, kubeconform
make drill    # backup and restore drill in Docker
```

The same targets run in CI on every push (`.github/workflows/ci.yml`).

## Create the environment on AWS

```bash
cd terraform/envs/dev
cp terraform.tfvars.example terraform.tfvars   # set the certificate ARN and your e-mail
terraform init
terraform plan
terraform apply
# ... use it, capture the evidence ...
terraform destroy
```

Costs while it is up, roughly: the load balancer, one `t4g.small` instance and
one `db.t4g.micro` database. The budget alert fires at 80% of USD 10.
